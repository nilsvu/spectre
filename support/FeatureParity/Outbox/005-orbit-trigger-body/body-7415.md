# Survey: orbit-based triggers, and the PN-time alternative

Feature-parity survey evidence. Revisions: SpEC @ sxs-collaboration/spec@5f8f5375ca, SpECTRE `develop` @ sxs-collaboration/spectre@4d43624d64 (2026-08-13; PN-time alternative folded in 2026-08-14). All `file:line` references are to these revisions.

## What SpEC has

- Exactly **one** orbit-based trigger: `Evolution/EvolutionObservers/FractionOfOrbit.cpp:34-162` — a stateful, checkpointed observer that tracks the swept angle of a mapped reference point and fires every `2π·frac`.
- Hard cap `frac <= 0.25` (`FractionOfOrbit.cpp:44-45`): at least 4 triggers per orbit. **"Every N orbits" is not expressible in SpEC** — and per the design below, SpECTRE does not need it as a trigger either.
- Production use: wave extraction for all bound-orbit BBH runs at `RatchetingObservationsPerOrbit = 400` (`DoMultipleRuns.input:211-215`). "Ratcheting" makes the observation period the running minimum of past periods (`FractionOfOrbit.cpp:147-158`), so the cadence never coarsens as the orbit speeds up.
- Negative result: grep over `Evolution/`, `Utils/`, `Observers/`, `ComputeItems/` finds no other orbit-count machinery.

## What SpECTRE has

- **No orbit-based trigger.** The wave-extraction cadence in `Inspiral.yaml` is `Slabs`/`TimeCompares` only — it does not track the orbital frequency through the inspiral.
- The building blocks exist:
  - `SeparationLessThan` (`src/Evolution/Triggers/SeparationLessThan.hpp:75-127`) is the precedent for a trigger reading `domain::Tags::FunctionsOfTime`.
  - **The orbital phase is available in closed form**: `QuaternionFunctionOfTime` stores the rotation as the derivative of an angle `PiecewisePolynomial` and exposes `angle_func(t)` and derivatives (`QuaternionFunctionOfTime.hpp:68,148-160`). SpEC accumulates the angle only because it lacks this — a SpECTRE trigger can be **stateless**, which is also required: `Trigger::operator()` is `const` and evaluated per element.
  - **The PN side exists too**: the T4 integrator behind `initial_orbital_parameters` returns `(orbits, time)` for a given `Ω0` (`nOrbitsAndTotalTime`; moving to SimulationSupport, #7412), and the ecc-control pipeline already terminates on a constant-Ω time estimate of 2.5 orbits (`FinalTime = 500 + 5π/Ω0`, `Inspiral.py:504-509`).
- Caveats a phase trigger must handle:
  - `angle_func` is not on the `FunctionOfTime` base class (the base `func*` return the quaternion).
  - The initial angles are documented as arbitrary (`QuaternionFunctionOfTime.hpp:45-48`) — a phase-counting trigger must difference against a reference.
  - The stored angle is a 3-vector — precession needs a phase definition.

## The two use cases split (from the #5938 discussion)

@nilsdeppe's suggestion on #5938 — *"Why not just specify a time? You can get an estimate of the time for a specific number of orbits from PN"* — is adopted for one of the two use cases:

- **Termination after ~N orbits** (#5938's ask): compute `T(N)` from PN at input-file generation and use the existing `TimeCompares` machinery. Pure pipeline change, no new trigger. Precedent: the ecc-control window already terminates on a time chosen this way (2.5 constant-Ω periods, adequate at that horizon — see design). For longer horizons (~tens of orbits) the chirp matters, which is where the 3.5PN T4 integration (`nOrbitsAndTotalTime`) comes in. This removes the need for an `EveryNOrbits` trigger entirely.
- **Observation cadence** (wave extraction N times per orbit, SpEC's 400/orbit): a PN-precomputed time schedule would drift from the actual evolution (junk transients, NR phase ≠ PN phase late in the inspiral). The rotation function of time is the **measured** phase — the `NTimesPerOrbit` trigger reads it directly and stays exact by construction. The trigger remains the right mechanism here.

## Prior art — read before starting

**PR #6009 "Add Fraction of Orbit Trigger"** (open, stale since 2025-08-12) is a substantially complete attempt: trigger + test + accumulated-angle support + BBH registration. The author's own note:

> there's something messed up in the logic of when the next check time should be. This causes an issue where the trigger never actually triggers.

So the open work is concentrated in the dense-trigger `next_check_time` — addressed concretely in the design below. Note `angle_func` exists on develop today; the PR's `QuaternionFunctionOfTime` diff needs re-checking before reuse.

Related: **#5938 "Stop inspiral after fixed number of orbits"** — resolved by the PN-time route above once the pipeline exposes it; no orbit trigger involved. Pattern references: PR #5150 (`SeparationLessThan`), #6409 (`InsideHorizon`), #2983 (dense triggers). Nothing else covers the cadence trigger.

**Scope note**: wiring the new trigger into `Inspiral.yaml`'s observation events is part of the deliverable, not a follow-up — SpEC's 400/orbit *is* the production wave-extraction cadence.

## Proposed design

**Part A — termination by PN time (pipeline only, resolves #5938).** A small helper (living with `initial_orbital_parameters`, i.e. in SimulationSupport once #7412 lands) inverts `nOrbitsAndTotalTime` to give `T(N orbits from Ω0)`; the pipeline exposes it (e.g. a `NumOrbits` option on the inspiral that fills `FinalTime`) and the existing `TimeCompares` trigger terminates the run. The T4 integration matters at this horizon — over ~20 orbits the chirp accumulates real error, unlike the ecc-control window. The existing ecc-control formula (2.5 constant-Ω periods, `Inspiral.py:504-509`) stays as is: over 2.5 orbits the period shrinks only a few percent, so the constant-Ω estimate overshoots harmlessly.

**Part B — one stateless trigger class, `NTimesPerOrbit`** (SpEC's `FractionOfOrbit` without the 0.25 cap), reading the cumulative orbital phase `Φ(t)` from `QuaternionFunctionOfTime::angle_func` and firing when `Φ(t)` crosses the next multiple of `2π/N`:

- `src/Evolution/Triggers/NTimesPerOrbit.{hpp,cpp}`, starting from PR #6009's `FractionOfOrbit` (renamed; its `QuaternionFunctionOfTime` diff re-checked against develop).
- Phase access: `dynamic_cast` the rotation function of time to `QuaternionFunctionOfTime` inside the trigger (pattern: `SeparationLessThan`). The trigger uses `Φ(t) − Φ(t_initial)` so the documented arbitrariness of the initial angles drops out.
- Dense-trigger variant for wave extraction: `next_check_time` inverts `Φ(t) = 2π k / N` by a scalar root-find (TOMS 748 on the angle `PiecewisePolynomial`) — exactly the defect that stalled #6009, now with a concrete fix.
- Registration in `EvolveGhBinaryBlackHole`; `Inspiral.yaml`'s wave-extraction/observation events switch from fixed `Slabs` intervals to `NTimesPerOrbit` (default: open point 5).

**Testing / acceptance**: Part A — the helper's `T(N)` matches the T4 integration in a unit test, and an inspiral launched with `NumOrbits` terminates within a few percent of `T(N)`. Part B — unit tests against analytic rotation functions of time (constant `Ω`: trigger times exactly `k·T/N`; chirping `Ω`: trigger count matches the analytic phase); a `next_check_time` test covering the #6009 failure mode; an input-file test exercising the dense-trigger path in the BBH executable.

## Open points to settle

- [ ] **1. Adopt the PN-time split** — termination via PN `T(N)` (Part A), trigger only for cadence (Part B), no `EveryNOrbits` trigger at all? Recommendation: yes — this is @nilsdeppe's #5938 suggestion; an exact-orbit-count termination use case would have to appear before a trigger is warranted.
- [ ] **2. `angle_func` access** — `dynamic_cast` in the trigger (recommendation: smaller first step) vs extending the `FunctionOfTime` interface.
- [ ] **3. Phase under precession** — z-component of the angle vector, projection on the instantaneous orbital angular momentum, or norm. Recommendation: norm — reduces to the z-component for non-precessing systems; document the choice.
- [ ] **4. Ratcheting** — reproduce SpEC's non-increasing-period behaviour, or rely on `Ω(t)` being monotone for quasicircular inspirals. Recommendation: skip initially.
- [ ] **5. PR #6009** — revive with its author or supersede explicitly — not reimplement silently.
- [ ] **6. Default cadence** in `Inspiral.yaml` — adopt SpEC's 400/orbit for wave extraction? Recommendation: yes.
